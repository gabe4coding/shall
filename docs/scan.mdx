# Scan

`shall scan` applies the code rules to whole files. It uses the same judgment as the hook that runs
after a write:

1. The secret scanner checks the raw text.
2. shall removes the secrets from the text.
3. shall sends one Jev request for each file. For each rule, p = min(applies, violates).

No agent runs.

## Run a scan

```bash
shall scan                          # the current folder: tracked and untracked files, not ignored files
shall scan src/ lib/client.py       # files or folders
shall scan --fail-on-blocking       # CI: exit 2 on a secret-scanner hit on an enforced MUST rule
shall scan --threshold 0.5          # more warnings: higher recall, more noise
```

The scan prints one line for each warning: `path[:line]: ID [level, p] title`. It writes `scan.md`
and `scan.json` to `--out-dir` (default `.shall-out`).

## Read the warnings

A Jev warning never blocks. One file is not sufficient evidence. Read the code before you change it,
or run `shall review` on the change to get verified findings. Only secret-scanner hits can block.

## What the scan skips

- Markdown documents
- Files that match `scan.exclude`: `node_modules`, `dist`, `vendor`, lock files and more
- Files larger than `scan.max_file_chars`

The scan uses the statuses in `selection.include_status`. To try draft rules, use
`--status draft,approved,enforced`. shall keeps the answers in a cache, so a second scan pays only for
the files that changed.

## Outputs and exit codes

| File | Content |
| --- | --- |
| `scan.md` | Warnings for each file, skipped files, files that Jev could not check |
| `scan.json` | The scores, findings and skips of each file, and the Jev usage |

| Code | Meaning |
| --- | --- |
| 0 | Done |
| 2 | Only with `--fail-on-blocking` (secret-scanner hits) or `--fail-on-warn` (any warning) |
| 3 | Jev failed for a file. A scan that skips files silently looks clean, so shall does not fail open here. |

## Measurements

Measured on 100 real files (`eval/scan`, [Results](./results.mdx#whole-file-scan-linting)):

- Cost: ~$0.0005 and ~0.4 s for each file. 48 files took 5 s with 4 requests at the same time.
- Precision 0.96 and recall 0.72 at p ≥ 0.7 on the held-out half, after the criteria fixes that the
  eval found.

Rules that a linter can check exactly, for example type hints or formatting, belong to a linter.
Mark them `Enforcement: linter`. shall does not send them to Jev.
