# CI

## GitHub Actions

1. Copy [`ci/github/jrfc-review.yml`](../ci/github/jrfc-review.yml) to `.github/workflows/` in
   your repository.
2. Change the lines with `TODO`: the tooling repository and its ref, and `JRFC_EXTENDS` if your
   repository has no `.jrfc/` folder.
3. Add these repository secrets:

   | Secret | Necessary for |
   | --- | --- |
   | `TYPESAFE_API_KEY` | Selection of the rules (Jev) |
   | `ANTHROPIC_API_KEY` | The review (`claude -p`) |
   | `JRFC_GIT_TOKEN` | Read access to the tooling and corpus repositories, if they are private |

4. Open a pull request. The job posts inline comments and one summary comment. It uploads
   `.jrfc-out/pr` as an artifact.
5. To block merges on enforced rules, make the `jrfc / review` job a **required check**. The job
   exits with code 2 when a blocking finding stays after verification.

## Other CI systems

Run this command from the root of the repository:

```bash
plugins/jrfc/bin/jrfc-pr-review --base origin/main --post 123 --fail-on-blocking
```

The header of [`jrfc-pr-review`](../plugins/jrfc/bin/jrfc-pr-review) lists all options. The command
uses `gh` to post. Add `--dry-run` to see the plan without a change to the pull request.

`jrfc publish` is the only step that writes outside the working directory. It is deterministic code.
Do not post the comments with `gh api`: `jrfc publish` prevents duplicate comments.

## Runs after each push

You can run the review after each push. It is safe, and it costs little:

- Each comment has a key from its rule and the content of its line. jrfc does not post the same
  finding two times. When a line is fixed, jrfc resolves its thread. A thread that a person resolved
  stays resolved.
- jrfc reviews a file again only when its diff, its rules or its known effects changed. It checks a
  blocking finding again only when its evidence changed. The answers stay in
  `.jrfc-cache/review.json`. The workflow keeps this cache for each pull request.

Example: a push that changed one file of a pull request with two files cost $0.15 instead of $0.39.
A run on an unchanged push cost $0.

## Triage of other AI reviewers

Add `--triage` to sort the comments of Copilot, CodeRabbit and other bots in the summary comment.
Add `--resolve-noise` to also answer and resolve each noise thread. Read [Triage](./triage.mdx).

## Cost

These are estimates for one review run, from measured unit costs:

- Claude review: $0.01–0.08 for each changed file where a rule applies
- Verification: approximately $0.015 for each blocking finding
- Jev: less than $0.003 for each file

| Pull request | Files reviewed | First run | Later pushes |
| --- | --- | --- | --- |
| Small | 1–3 | ~$0.05–0.15 | Only the files that changed |
| Medium | 5–10 | ~$0.30–0.60 | Only the files that changed |
| Large | 20–40 | ~$1.20–2.50 | Only the files that changed |

jrfc does not send a file to Claude when no rule applies to it, for example a style sheet.

## The corpus repository

The repository of your standards needs its own checks. Copy
[`ci/github/jrfc-corpus.yml`](../ci/github/jrfc-corpus.yml). It runs the lint, the index check and
the id stability check on each pull request. It does not call a model. Read
[Standards → Create a corpus](./standards.mdx#create-the-corpus-of-your-organisation).
